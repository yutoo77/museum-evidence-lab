# 閉域 RAG 比較用の架空資料と質問

自作の架空資料24件と質問54問です。研究資料、科学館の内部文書、来館者の情報は含みません。施設名・展示番号・運用値は架空で、科学的記述を含め専門家による校閲は未実施です。

開発用30問と留保用24問は、原本ごとに分けています。開発用は光・音・天文を中心とする架空の青星科学館、留保用は岩石・植物・水・振り子を中心とする架空の砂丘ラボです。同じ原本の言い換え質問を別の組へ移す分割にはしていません。ただし、両方とも同じ開発工程で自作しており、独立した研究者が作った外部評価ではありません。

## 何を測るか

| 指標 | 意味と限界 |
|---|---|
| 回答した割合 | 速くても回答を控えてばかりになっていないか |
| 回答できない質問への誤回答率 | 正解ラベルが回答不可の試行のうち、回答した割合 |
| 回答できる質問への過剰拒否率 | 正解ラベルが回答可能の試行のうち、拒否・聞き返し・要確認にした割合。通信等のエラーは別集計 |
| 必須語句・禁止語句 | 指定文字列が出たかという粗い点検。言い換え、否定、文脈は判断できず、正答率ではない |
| 引用原文一致 | 指定した根拠内に引用文字列が本当にあるか。主張の意味的な支持や科学的正しさは保証しない |
| 主張と引用の文字列一致 | 原文をそのまま見せた割合。引用先の原本が正しいという保証ではない |
| 根拠資料の再現率 | 回答可能な質問に必要な原本が検索根拠に含まれた割合。どのページが適切かは別確認 |
| 応答時間の中央値・95パーセンタイル | 初回の準備条件、質問の再利用、回答状態ごとに集計。20件未満は少数サンプルと表示 |
| エラー・途中終了 | 回答拒否とは別に件数を表示 |

「回答した／控えた」が想定と一致しても、正しい回答だったとは限りません。すべての実行で `manual_review.csv` を出力し、科学的正しさ、各文の根拠、拒否の妥当性を人が記入する欄を残します。検査していない欄を自動で合格扱いにはしません。

質問には、資料内の事実、数値・単位・日付、複数資料の比較、情報不足、無関係、曖昧な指示語、両方が有効な矛盾資料、未承認の旧版、将来適用予定の資料、資料に混入した不正な命令を含めています。命令入り資料は「資料全体を保留する」方針の評価です。命令だけを除去して答えられることを要求する評価ではありません。

## 実行

比較版の依存関係とローカルモデルを準備し、比較版専用の Ollama が起動している状態で、比較版フォルダから実行します。

```powershell
.\.venv\Scripts\python.exe -m src.lab.evaluate --config lab_config.yaml --split dev --modes baseline quoted concise bounded --models qwen3:1.7b --run-id dev-first
```

短い動作確認は `--limit 3`、繰り返しは `--repeat 2` を追加します。同じ `--run-id` は再利用できません。先頭だけを抜き出す `--limit` は回答可能な質問に偏るため、全体の品質評価やモデル順位には使えません。

留保用は開発用で実装・プロンプトを決めてから実行します。

```powershell
.\.venv\Scripts\python.exe -m src.lab.evaluate --split holdout --modes quoted concise bounded --models qwen3:1.7b --run-id holdout-first
```

CLI はモデルの取得・停止・事前読込を暗黙には行いません。`--first-query-state cold` / `warm` は、実際に準備した状態を実行者が申告するオプションです。指定しなければ未管理と記録します。資料登録で検索モデルはすでに使用されるため、これは回答モデルの準備についての申告です。2問目以降もモデルの追い出しはあり得るため、自動で「温まった」とは断定しません。応答にはロード・入力処理・出力処理の時間とトークン数も保存します。

各モデルで同じ順に質問するため、モデル間で質問露出順は揃います。モード間ではモデルやプロンプトのキャッシュが共有されます。2つ目のモードが同じ質問を受けた結果を「未知の質問」と数えません。繰り返す場合はモード順を回転させますが、厳密な無作為化比較ではありません。初回・準備済みの比較は、別 run で準備を揃えて行ってください。

## 保存先と再現性

`outputs/lab-comparisons/<run-id>/<モデル>/` に、当該 split の資料だけを入れた専用索引と評価結果を保存します。通常のアプリの登録資料を混ぜません。モデルごとの索引も分離し、検索モデルの名前・重みの識別値・分割条件を索引で照合します。

`report/` には次のファイルが生成されます。

- `results.jsonl`：各質問の最終回答・根拠の引用・工程別時間。内部の思考過程は含まない。
- `report.json`：分母を明示した自動点検結果。意味的な正しさは未確認と表示。
- `manifest.json`：質問、各原本、設定のハッシュ、使用モデルと重みの識別値、実効設定、Pythonと依存関係の版、実行日時。
- `manual_review.csv`：人が内容を点検するための表。未記入で作成。

`baseline` は、旧版に近い「密な検索の上位5件→回答可否判定→回答生成」の参照方式です。原本の承認・有効日管理と索引は比較版共通です。旧アプリの Chroma/HNSW 索引や画面・保存処理を完全再現した比較ではありません。旧アプリと同じ速度という意味で使わないでください。

留保用の結果を見てから変更を加えたり、複数回試して良い結果だけを選んだ場合、その組は開発情報になります。レポートは留保用でも探索的結果と表示します。修論や実利用の主張には、未使用の追加問題、実資料の利用許可、専門家の回答確認が必要です。

## データを直す場合

`corpus_manifest.json` に原本ごとの承認状態と適用日を記録します。`cases.jsonl` の原本パスは `dev/` または `holdout/` で始め、質問と同じ組に限定します。回答可能ラベルでは必須語句と根拠資料を必ず指定します。回答可能と回答不可を同じ正解ラベルに混在させることはできません。

旧版・将来資料の「今」は実行日のローカル日付を使います。将来テストは2099年1月1日より前を対象とします。過去の結果と比べるときは、日時・原本ハッシュ・設定・モデルの重みを合わせてください。
